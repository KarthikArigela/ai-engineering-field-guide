Five Archetypes - The Split

Green = RAG/application-heavy · Blue = platform-heavy · Red = training/infra-heavy

1. Agent Builder - 28.6%

1,990 postings, 88% ai-first - now the largest archetype


Builds and runs agents - via provider APIs, frameworks, or both. (Merged from two k-means clusters that split almost entirely on whether "Prompt Engineering" was tagged as a skill, 97% vs 0% - not a real difference in the work.)

  • Agents - 88% (x1.6 lift)
  • Prompt Engineering - 51% (x1.5)
  • Function Calling - 23% (x1.7)
  • MCP - 19% (x1.3)
  • RAG - 39% (x1.0, roughly baseline)

2. RAG App Builder - 25.3%

1,763 postings, 96% ai-first


Connects LLMs to a company's own data: documents, databases, internal knowledge.

  • RAG - 90% (x2.1 lift)
  • Vector databases - 71% (x2.6)
  • LangChain - 65% (x2.8)
  • LangGraph - 41% (x2.8)
  • Fine-Tuning - 36% (x2.1)

3. Cloud / ML Platform Engineer - 18.0%

1,257 postings, only 58% ai-first


Runs the multi-cloud infrastructure and serving layer that AI systems sit on.

  • AWS - 94% (x2.2)
  • GCP - 88% (x3.0)
  • Azure - 88% (x2.8)
  • PyTorch/TensorFlow - 33% (x1.7)
  • Kubernetes - 36% (x1.4), inference/serving - 26% (x1.5)

4. DevOps / Full-Stack Engineer - 13.3%

923 postings, only 33% ai-first - least AI-native cluster


General software/infra engineering with AI layered on top, not the focus.

  • CI/CD - 72% (x1.8)
  • Kubernetes - 47% (x1.8)
  • Docker - 44% (x1.7)
  • React/frontend - 41% (x2.4)
  • Terraform - 26% (x2.4)

5. ML Trainer / Researcher - 8.2%

571 postings, 46% ai-first - the smallest archetype


Classic ML work: training and serving models, not integrating LLMs into apps.

  • PyTorch/TensorFlow - 62% (x3.1)
  • Inference/serving - 52% (x3.0)
  • MLOps - 31% (x1.5)
  • SQL - 22% (x1.4)

% of postings whose use cases match, all 8 scrapes

What Companies Build

  • Automation / workflow: 52.2% → 59.6% - still the dominant use case
  • Agents / autonomous: 43.0% → 48.9%
  • RAG / Q&A: 13.6% → 20.6% - up more than half
  • Recommend / personalize: 12.8% → 7.0% - fading

The Training Stack Keeps Declining

Skill Momentum: Risers vs Decliners

Two Distinct Stacks, Still

Skill co-occurrence lift across all 6,964 jobs

  • LangChain → LangGraph 46% of the time (x3.3 lift) - strongest pair in the dataset
  • RAG → embeddings (x2.2), vector DBs (x2.0), function calling (x1.9)
  • PyTorch → MLOps (x2.2), Kubernetes (x1.4)


Even Fine-Tuning has switched sides: it now co-occurs more with RAG/agent skills than with PyTorch/training skills - today it usually means adapting an LLM for an app, not training a model from scratch

Part 4

What Still Hasn't Happened

The "AI Infra Engineer" Still Isn't a Role

Inference/serving = running models in production: vLLM, Triton, TensorRT, CUDA, model deployment

19.8% → 9.9%

share of ai-first jobs that mention this work - roughly halved


There's no dedicated "AI infra engineer" job category forming. That work keeps getting folded into the general Cloud/ML Platform archetype (archetype #2) instead of becoming its own specialized title.

Forward Deployed Engineer

187 postings, 2.7%

Feb 2.0% → peaked 4.4% in July


  • 89% customer-facing (vs 14% for other ai-first roles)
  • 72% agents, only 47% RAG - agent-heavy generalists
  • Only 10% PyTorch/TF - less research, more delivery

Junior hiring has stayed pinned near 1% the entire eight months. Now Staff+ is thinning too.

Key Takeaways

  • ai-first share is stable (68-71%), not rising - no consolidation trend either direction
  • Integrator-vs-trainer shift is real and accelerating: 80% → 88% integrator within ai-first
  • Prompt Engineering and RAG are the fastest-rising named skills, not SQL
  • Agent-building is fragmenting into more specific sub-roles, not consolidating
  • AI infra still isn't a standalone role; junior hiring is still closed
